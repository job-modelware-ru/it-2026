# Описание БД

СУБД — PostgreSQL (по нефункциональным требованиям). В базе хранятся учётные записи студентов, справочник алгоритмов, теоретические материалы и всё, что связано с экспериментами. Сами CSV-файлы и файлы обученных моделей лежат на диске сервера, в БД хранятся только пути к ним.

Гость в БД не хранится: про него системе ничего не известно, а теоретические материалы он только читает.

Скрипты: `sql/01_create_database.sql` — создание таблиц, `sql/02_test_data.sql` — тестовые данные, `sql/03_queries.sql` — основные запросы.

## Модуль «Пользователи и авторизация»

### users

- **Назначение:** учётные записи студентов.
- **Поля:**
  - `user_id`: SERIAL, PRIMARY KEY — идентификатор пользователя.
  - `name`: VARCHAR(100), NOT NULL — имя.
  - `email`: VARCHAR(255), NOT NULL, UNIQUE — e-mail, используется для входа.
  - `password_hash`: VARCHAR(255), NOT NULL — хеш пароля (bcrypt или Argon2).
  - `status`: VARCHAR(20), NOT NULL, DEFAULT 'inactive', CHECK ('inactive', 'active') — статус учётной записи. Войти можно только после активации по ссылке из письма.
  - `created_at`: TIMESTAMP, NOT NULL, DEFAULT CURRENT_TIMESTAMP — дата регистрации (показывается в профиле).
  - `updated_at`: TIMESTAMP, NOT NULL, DEFAULT CURRENT_TIMESTAMP — дата последнего изменения профиля.

### account_activation_tokens

- **Назначение:** токены из письма для активации учётной записи.
- **Поля:**
  - `token`: VARCHAR(64), PRIMARY KEY — случайный токен из ссылки.
  - `user_id`: INT, NOT NULL, FOREIGN KEY → users(user_id), ON DELETE CASCADE — чей токен.
  - `expires_at`: TIMESTAMP, NOT NULL — срок действия ссылки.
- **Индексы:** по `user_id` — для повторной отправки письма.
- После активации токен удаляется. Кнопка «Отправить письмо повторно» заменяет старый токен новым.

## Модуль «Теоретические материалы»

### algorithms

- **Назначение:** справочник алгоритмов. Записей ровно четыре: линейная регрессия, логистическая регрессия, случайный лес, kNN.
- **Поля:**
  - `algorithm_id`: SERIAL, PRIMARY KEY — идентификатор алгоритма.
  - `code`: VARCHAR(50), NOT NULL, UNIQUE — код для API: 'linear_regression', 'logistic_regression', 'random_forest', 'knn'.
  - `name`: VARCHAR(100), NOT NULL, UNIQUE — название для интерфейса.
  - `task_type`: VARCHAR(20), NOT NULL, CHECK ('regression', 'classification', 'both') — для каких задач подходит алгоритм.

### theory_materials

- **Назначение:** страницы информационного раздела — 4 страницы методов и 2 страницы справочника метрик (регрессия и классификация).
- **Поля:**
  - `material_id`: SERIAL, PRIMARY KEY — идентификатор страницы.
  - `section`: VARCHAR(20), NOT NULL, CHECK ('method', 'metrics') — раздел: теория метода или справочник метрик.
  - `algorithm_id`: INT, FOREIGN KEY → algorithms(algorithm_id), ON DELETE SET NULL — какой метод описывает страница. Для справочника метрик — NULL.
  - `title`: VARCHAR(255), NOT NULL — заголовок.
  - `content`: TEXT, NOT NULL — текст страницы.
  - `updated_at`: TIMESTAMP, NOT NULL, DEFAULT CURRENT_TIMESTAMP — дата обновления.
- **Ограничение:** у страницы метода `algorithm_id` заполнен, у страницы справочника метрик — пуст.

## Модуль «Эксперименты»

### datasets

- **Назначение:** CSV-файлы, загруженные студентами.
- **Поля:**
  - `dataset_id`: SERIAL, PRIMARY KEY — идентификатор датасета.
  - `user_id`: INT, NOT NULL, FOREIGN KEY → users(user_id), ON DELETE CASCADE — кто загрузил.
  - `name`: VARCHAR(255), NOT NULL — имя файла.
  - `description`: TEXT — описание (необязательно).
  - `file_path`: VARCHAR(500), NOT NULL, UNIQUE — путь к файлу на сервере.
  - `file_size`: BIGINT, NOT NULL, CHECK (0 < file_size ≤ 104 857 600) — размер в байтах, не больше 100 МБ.
  - `uploaded_at`: TIMESTAMP, NOT NULL, DEFAULT CURRENT_TIMESTAMP — дата загрузки.
- **Индексы:** по `user_id`.

### experiments

- **Назначение:** эксперименты студентов. Запись создаётся при нажатии «Обучить модель» со статусом 'running' и дополняется по завершении обучения.
- **Поля:**
  - `experiment_id`: SERIAL, PRIMARY KEY — идентификатор эксперимента.
  - `user_id`: INT, NOT NULL, FOREIGN KEY → users(user_id), ON DELETE CASCADE — кто провёл.
  - `dataset_id`: INT, NOT NULL, FOREIGN KEY → datasets(dataset_id), ON DELETE RESTRICT — на каком наборе данных.
  - `algorithm_id`: INT, NOT NULL, FOREIGN KEY → algorithms(algorithm_id), ON DELETE RESTRICT — каким алгоритмом.
  - `task_type`: VARCHAR(20), NOT NULL, CHECK ('regression', 'classification') — тип задачи.
  - `target_column`: VARCHAR(255), NOT NULL — целевая переменная.
  - `feature_columns`: TEXT[], NOT NULL — выбранные признаки, хотя бы один.
  - `status`: VARCHAR(20), NOT NULL, DEFAULT 'running', CHECK ('running', 'completed', 'failed') — статус.
  - `started_at`: TIMESTAMP, NOT NULL, DEFAULT CURRENT_TIMESTAMP — время начала.
  - `finished_at`: TIMESTAMP — время окончания. Пусто, пока эксперимент идёт.
  - `error_message`: TEXT — текст ошибки, если обучение не удалось.
  - `plot_data`: JSONB — данные для графиков и матрицы ошибок на странице результатов и в деталях эксперимента.
- **Ограничения:**
  - целевая переменная не может быть среди признаков;
  - `finished_at` не раньше `started_at`;
  - у эксперимента со статусом 'running' нет `finished_at`, у завершённого — есть.
- **Индексы:**
  - (`user_id`, `started_at` DESC) — история экспериментов, новые сверху;
  - (`user_id`, `algorithm_id`) — фильтр истории по алгоритму;
  - по `dataset_id`.

### experiment_settings

- **Назначение:** значения гиперпараметров эксперимента (класс «Настройка» из модели предметной области). У каждого алгоритма свой набор гиперпараметров, поэтому они хранятся строками «название — значение», а не отдельными столбцами.
- **Поля:**
  - `setting_id`: SERIAL, PRIMARY KEY — идентификатор.
  - `experiment_id`: INT, NOT NULL, FOREIGN KEY → experiments(experiment_id), ON DELETE CASCADE.
  - `param_name`: VARCHAR(100), NOT NULL — название гиперпараметра (n_neighbors, max_depth, test_size…).
  - `param_value`: VARCHAR(255), NOT NULL — значение.
- **Ограничения:** UNIQUE (`experiment_id`, `param_name`) — один гиперпараметр в эксперименте задаётся один раз.

### experiment_metrics

- **Назначение:** метрики качества эксперимента (класс «РезультатЭксперимента»).
- **Поля:**
  - `result_id`: SERIAL, PRIMARY KEY — идентификатор.
  - `experiment_id`: INT, NOT NULL, FOREIGN KEY → experiments(experiment_id), ON DELETE CASCADE.
  - `metric_name`: VARCHAR(50), NOT NULL — название метрики: mae, mse, rmse, r2_score для регрессии; accuracy, precision, recall, f1_score, roc_auc для классификации.
  - `metric_value`: DOUBLE PRECISION, NOT NULL — значение.
- **Ограничения:** UNIQUE (`experiment_id`, `metric_name`).

### trained_models

- **Назначение:** обученные модели, которые можно скачать. У эксперимента не больше одной модели; у неудачного эксперимента модели нет.
- **Поля:**
  - `model_id`: SERIAL, PRIMARY KEY — идентификатор.
  - `experiment_id`: INT, NOT NULL, UNIQUE, FOREIGN KEY → experiments(experiment_id), ON DELETE CASCADE — эксперимент, который породил модель.
  - `file_path`: VARCHAR(500), NOT NULL, UNIQUE — путь к файлу модели.
  - `created_at`: TIMESTAMP, NOT NULL, DEFAULT CURRENT_TIMESTAMP — дата создания.
  - `expires_at`: TIMESTAMP, вычисляемое: `created_at` + 30 дней — до какого момента модель хранится.
- **Индексы:** по `expires_at` — для ежедневной очистки.
- Через 30 дней запись и файл удаляются (НФТ), метрики эксперимента остаются. Кнопка «Скачать модель» видна, пока запись есть.

## Соответствие модели предметной области

| Модель предметной области | Таблица | Что добавлено |
|---|---|---|
| Пользователь (абстрактный), Гость | — | не хранятся |
| Студент | users | дата регистрации и изменения |
| — | account_activation_tokens | нужна для подтверждения e-mail (НФТ «Безопасность») |
| ТеоретическиеМатериалы | theory_materials | раздел (метод / метрики) и ссылка на алгоритм |
| Алгоритм | algorithms | код для API |
| Датасет | datasets | владелец, путь и размер файла, дата загрузки |
| Эксперимент | experiments | тип задачи, целевая переменная, признаки, текст ошибки, данные графиков |
| Настройка (класс-ассоциация) | experiment_settings | — |
| РезультатЭксперимента | experiment_metrics | — |
| ОбученнаяМодель | trained_models | срок хранения |

Ассоциация «Имеет доступ» (Пользователь — ТеоретическиеМатериалы) в БД не отражается: материалы открыты всем, хранить факт доступа не нужно.

## Порядок заполнения

С учётом внешних ключей таблицы заполняются так:

1. **users** — пользователи регистрируются.
2. **account_activation_tokens** — токен создаётся вместе с пользователем при регистрации.
3. **algorithms** — справочник алгоритмов заполняется один раз при развёртывании.
4. **theory_materials** — страницы методов ссылаются на алгоритмы.
5. **datasets** — студент загружает CSV.
6. **experiments** — запись создаётся при запуске обучения.
7. **experiment_settings** — гиперпараметры сохраняются вместе с экспериментом (одна транзакция).
8. **experiment_metrics** — метрики добавляются по завершении обучения.
9. **trained_models** — модель сохраняется по завершении успешного обучения.

## Служебные задачи

Запускаются по расписанию, запросы — в конце `sql/03_queries.sql`:

- удалить модели старше 30 дней (приложение удаляет файлы по возвращённым путям);
- завершить со статусом 'failed' эксперименты, которые обучаются дольше 5 минут (таймаут из НФТ);
- удалить просроченные токены активации.
